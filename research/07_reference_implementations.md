# Reference Implementations: Concrete Repos and Tutorials to Study or Fork

`01_simulation_platforms.md` surveyed *platforms*; this file surveys *actual code built on top of them* — specific GitHub repositories and tutorial series a solo developer could realistically clone, read end-to-end, and learn from or extend. For each, what's actually inside, how current/maintained it is (checked directly against GitHub's API as of this research pass), and an honest quality verdict rather than a name-drop.

## By simulator, in more depth

### highway-env ecosystem — the best-supported "learn the pipeline" tier
Beyond the SB3 quickstart in highway-env's own docs, [`eleurent/rl-agents`](https://github.com/eleurent/rl-agents) is worth reading in full: it's written by the same author as highway-env itself (Edouard Leurent), and implements not just DQN but budgeted tree-search planning algorithms (MCTS variants, robust/pessimistic MDP planning) specifically evaluated against highway-env's own scenario families. This is a genuinely good place to see planning-flavored methods (conceptually adjacent to the MPC-style lookahead in TD-MPC2, see `08`) applied to a driving task with mature, documented code, rather than either a pure textbook DQN or a from-scratch research codebase. Separately, [`DLR-RM/rl-baselines3-zoo`](https://github.com/DLR-RM/rl-baselines3-zoo) — the companion project to Stable-Baselines3 itself — ships pre-tuned hyperparameters and (for many Gym environments) trained-agent checkpoints plus an Optuna-based hyperparameter search harness; using it against highway-env is the fastest way to get a credible non-trivial baseline running before writing any custom training code.

### CARLA — a real spread from "abandoned but readable" to "still alive"
Checked directly (Sept 2026): [`bitsauce/Carla-ppo`](https://github.com/bitsauce/Carla-ppo) (last push Nov 2021) and [`Luca96/carla-driving-rl-agent`](https://github.com/Luca96/carla-driving-rl-agent) (last push Mar 2023, pinned to CARLA 0.9.9) are both genuinely well-engineered but effectively frozen research artifacts — expect to spend real time porting them to a current CARLA version rather than running them as-is. The standout exception is [`idreesshaikh/Autonomous-Driving-in-Carla-using-Deep-Reinforcement-Learning`](https://github.com/idreesshaikh/Autonomous-Driving-in-Carla-using-Deep-Reinforcement-Learning), which had commits as recently as November 2025 and has accumulated 563 stars — by a meaningful margin the most currently-relevant solo CARLA+RL repo found in this research pass; it combines PPO with a VAE for observation compression, the same core trick as `araffin`'s Donkey Car project (see `12`). For multi-agent CARLA specifically, [`praveen-palanisamy/macad-gym`](https://github.com/praveen-palanisamy/macad-gym) (NeurIPS 2019 workshop paper, JSON-configurable scenarios, native RLlib pairing) remains the standard reference even though its last push was 2023; [`johnMinelli/carla-gym`](https://github.com/johnMinelli/carla-gym) is a newer, lighter PettingZoo-based alternative if you'd rather avoid RLlib's API surface (see `08`).

### Duckietown — the official baselines are the trustworthy path
Because Duckietown is explicitly education-first, the platform team itself maintains [`challenge-aido_LF-baseline-RL-sim-pytorch`](https://github.com/duckietown/challenge-aido_LF-baseline-RL-sim-pytorch) as the canonical RL entry point for the AI Driving Olympics lane-following track — this is a meaningfully different trust posture than the CARLA repos above (which are all third-party solo efforts of varying freshness). [`kaland313/Duckietown-RL`](https://github.com/kaland313/Duckietown-RL) is the smaller, paper-specific companion if sim-to-real transfer specifically is your interest.

### Donkey Car — where the single best-documented solo project on this list lives
`tawnkramer/gym-donkeycar`'s own `examples/reinforcement_learning/` folder ships both DDQN (`ddqn.py`) and PPO (`ppo_train.py`) reference scripts, and the parent repo is actively maintained (pushed as recently as March 2026) — a genuinely rare thing among the platforms surveyed here. But the project actually worth reading in full is [`araffin/learning-to-drive-in-5-minutes`](https://github.com/araffin/learning-to-drive-in-5-minutes) (Antonin Raffin, later a Stable-Baselines3 core maintainer) — full writeup in `12_small_scale_case_studies.md`, since it's less "a repo to fork" and more "a case study in how a well-chosen representation trick (VAE) makes an RL problem tractable at hobbyist scale."

### The world-model-specific track — thin, but CarDreamer is real and usable
[`ucd-dare/CarDreamer`](https://github.com/ucd-dare/CarDreamer) (369 stars, actively maintained) is the one platform on this entire list that packages a mature world-model algorithm (DreamerV2/V3, Plan2Explore) behind a standardized Gym interface specifically for CARLA. There is no equivalent for TD-MPC2 — see `08_training_frameworks_and_tdmpc2_gap.md` for exactly what that gap looks like and what closing it would take. A blog-level (not a maintained repo) comparison of DreamerV3 vs. TD-MPC in CARLA exists — [Driving With Imagination](https://satyamcser.substack.com/p/driving-with-imagination-dreamerv3), already cited in `02` — and remains, as of this research pass, one of the only public artifacts putting the two head-to-head in a driving context at all.

### Offline RL on real logs — one concrete repo to point at
[`AntonioAlgaida/WaymoOfflineRL`](https://github.com/AntonioAlgaida/WaymoOfflineRL) reproduces the CQL-vs-BC comparison described in `02` and `11` (entity-centric transformer state, CQL achieving roughly 3× the success rate and ~7× lower collision rate than the strongest BC baseline on held-out WOMD scenarios) — worth cloning specifically if your interest tilts toward "learn from real logged driving without live simulation" rather than "train live against a simulator."

## The honest pattern across all of these

Almost none of the CARLA-specific solo repos are actively maintained past 1-2 years — CARLA's own API surface moves fast enough that third-party wrapper repos age out quickly, and you should budget real porting time rather than expecting `git clone && pip install -r requirements.txt` to just work. The lightweight-simulator repos (highway-env, Donkey Car) age much more gracefully because the underlying environments themselves change less. The single most reusable pattern across the *well-engineered* projects here — `araffin`'s VAE+SAC Donkey Car project and `idreesshaikh`'s VAE+PPO CARLA project both do this — is compressing high-dimensional pixel observations into a small learned latent space (a VAE) *before* handing them to an off-the-shelf RL algorithm from a mature library, rather than either using privileged state (fast but unrealistic) or feeding raw pixels directly into the RL algorithm's own network (slow, high-variance). That's a concrete, reusable engineering pattern independent of which specific repo you start from.
